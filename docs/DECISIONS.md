# 설계 결정 기록 (ADR 요약)

주요 결정과 근거. 나중에 "왜 이렇게 했지?" 를 줄이기 위한 기록.

## D1. 기본 모드는 무조건 paper
- **결정**: 첫 실행/기본 설정은 가상매매. 실주문은 명시적 활성화 필요.
- **근거**: 검증되지 않은 전략의 실거래 손실 방지. PRD §24 핵심 원칙 1·3.

## D2. AI 는 점수화만, 주문 권한 없음
- **결정**: 모델은 성공확률 산출까지. 주문 결정/실행은 룰+리스크+사용자.
- **근거**: 모델 오류가 곧 손실이 되지 않도록 분리. PRD §11.1, §24-2.

## D3. 3m/5m 캔들은 1m 합성
- **결정**: 토스 API 가 `1m`/`1d` 만 제공 → `candles.resample` 로 N분봉 생성.
- **근거**: 스펙 제약(API_NOTES.md). 별도 합성으로 전략 레이어는 임의 분봉 사용 가능.
- **영향**: 합성 정확도는 1m 데이터 연속성에 의존. 결손 구간 처리 필요.

## D4. 실시간은 REST 폴링 (WebSocket 미지원)
- **결정**: 스캔 주기 폴링으로 시세 수집. WS 는 추후 지원 시 도입.
- **근거**: 스펙상 "웹소켓 추후 지원". 
- **영향**: 단타 체결/슬리피지 민감 → paper 라벨링을 보수적으로, trades(틱) 활용.

## D5. 토큰 캐싱 (client당 1개 제약)
- **결정**: access token 을 메모리 캐시, 만료 임박(margin) 시에만 재발급.
- **근거**: client당 유효 토큰 1개 — 무분별 재발급은 기존 토큰 무효화. 멀티 인스턴스 주의.
- **위치**: `api/client.py`.

## D6. 비용(수수료·세금·슬리피지)을 paper 단계부터 반영
- **결정**: 가상매매 손익에 commissions/거래세/호가 슬리피지 반영.
- **근거**: +0.5% 익절 전략은 비용 미반영 시 실거래에서 마이너스가 되기 쉬움.
- **데이터**: `/commissions`, holdings `cost`, 체결 `commission`/`tax`, `amountAfterCost`.

## D7. 중복 주문 방지는 멱등성 키 사용
- **결정**: 주문 생성 시 `clientOrderId`(10분 유효) 설정.
- **근거**: 네트워크 재시도/중복 클릭에도 단일 주문 보장. PRD R10.

## D8. 관심종목은 앱 내부 YAML 관리
- **결정**: 토스 앱 관심종목을 API 로 가져오지 않고 `config/favorites.yaml` 로 관리.
- **근거**: 해당 기능 초기 범위 외. PRD §4.3, §24-9.

## D9. Python + Typer + httpx + SQLite + scikit-learn 스택
- **결정**: CLI MVP 에 적합한 경량 스택. (PRD §20 1안)
- **근거**: API 연결·데이터 분석·ML 실험·MD 리포트가 모두 빠름. UI 는 추후 Tauri 분리.

## D10. 현재 코드 위치: stock-auto-trader (main)
- **경위**: 최초 Yuseok 저장소에서 작업 후 stock-auto-trader 로 이전.
- **권고**: 이후 개발은 stock-auto-trader 단일 저장소에서 진행.
