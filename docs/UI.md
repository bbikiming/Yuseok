# 화면 (로컬 웹 UI)

주식을 잘 모르는 사람도 쓸 수 있게 만든 화면이다. 터미널 명령을 외우지 않아도
키 연결 → 과거 기록 받기 → 과거로 시험 → 연습 매매까지 브라우저에서 할 수 있다.

```bash
tradebot ui --demo     # 키 없이 가상 데이터로 둘러보기 (약 3분짜리 시나리오)
tradebot ui            # 실제 사용. http://127.0.0.1:8765 가 열린다
tradebot ui --port 9000 --no-open
tradebot ui --phone    # 같은 와이파이의 휴대폰에서도 열기 (접속 코드 필요)
```

저장소 폴더(설정 `config/` 가 있는 곳)에서 실행한다. 끝낼 때는 터미널에서 Ctrl-C.

## 설계 원칙

1. **퍼센트보다 원.** "+0.9%" 대신 "약 +2,004원". 수수료·세금을 뺀 금액을 보여 준다.
2. **용어보다 문장.** "손절가 도달" 대신 "가격이 98,800원 아래로 내려가서 약속대로 팔았어요".
3. **연습이라는 사실을 항상 보이게.** 모든 화면 위에 "연습 모드 · 실제 주문 없음" 표시.
   실제 주문을 켜는 버튼·설정은 없다 (그런 코드 자체가 없다).
4. **근거 없는 숫자를 만들지 않는다.** 승률·누적 수익은 실제 기록에서만 계산한다.
   기록이 모자라면 "아직 판단할 수 없어요"라고 말한다.
5. **불리한 사실도 그대로.** 지금 기본 설정은 주식 기준 10번 중 6번을 이겨야 본전이라는 것,
   손절은 한 칸 낮은 가격에 팔린 것으로 계산한다는 것을 화면에 적는다.
6. **색 약속은 한국 증시 관례.** 오르면 빨강, 내리면 파랑. 색만으로 구분하지 않고 ▲▼·글자를 함께 쓴다.
7. **겉모습은 토스 디자인 시스템(TDS)을 따른다.** 아래 "디자인" 절 참고.

## 화면

| 화면 | 주소 | 내용 |
|---|---|---|
| 홈 | `#/` | 지금 상태 한 문장 + 다음에 할 일 버튼, 실전까지 5단계, 진행 중인 연습 매매(목표가·손절가 사이 어디쯤인지), 한 번 거래하면 오가는 금액, 오늘 있었던 일 |
| 신호 | `#/signals` | 오늘 연습으로 산 기록 목록 |
| 신호 상세 | `#/signal/<id>` | 왜 샀는지(그래프 + 세 문장), 언제 파는지(세 가지 경우와 금액), 끝났으면 결과와 계산 내역 |
| 관심종목 | `#/favorites` | 지켜볼 종목 켜기/끄기·추가·삭제, 종목 고르는 요령 |
| 과거로 시험 | `#/backtest` | 과거 기록 받기, 규칙이 과거에 통했는지 판정(통과 / 통과 못 함 / 판정 보류) |
| 연습 기록 | `#/history` | 지금까지의 연습 결과 합계, 50번 중 몇 번 쌓였는지, 전체 목록 |
| 설정 | `#/settings` | 토스증권 키 연결, 거래 규칙(금액·목표·손절·시간·횟수·수수료·세금), 바꾼 값에 따른 금액 미리보기 |

PC는 위쪽 메뉴 줄, 760px 이하(모바일)는 아이콘이 있는 아래 탭으로 바뀐다. 같은 페이지 한 장이 두 형태를 겸한다.
오른쪽 위 해·달 버튼으로 밝은 화면과 어두운 화면을 바꾼다 (처음에는 시스템 설정을 따르고, 고른 값은 브라우저에 기억된다).

### 오른쪽 옆 패널 (좁은 화면에서는 "내 현황" 시트)

토스증권 PC 처럼 화면 오른쪽에 아이콘 줄이 있고, 누르면 패널이 열린다. 같은 아이콘을 다시 누르면 닫힌다.
어느 화면에 있든 계속 보이고 2.5초마다 스스로 갱신된다 (본문은 다시 그리지 않아서 입력 중인 값이 지워지지 않는다).

| 아이콘 | 내용 |
|---|---|
| 연습 매매 | 오늘 끝난 매매의 합계, 진행 중인 매매(지금 가격·손익), 오늘 끝난 매매 목록. 진행 중인 매매가 있으면 아이콘에 빨간 점 |
| 관심 | 관심종목의 지금 가격과 등락률(전일 종가 대비). 연습(감시) 중일 때만 나온다. 꺼 둔 종목은 "쉬는 중" |
| 최근 본 | 최근에 열어 본 신호 10개 (이 브라우저에만 기억) |
| 실시간 | 오늘 있었던 일을 시간순으로 |

- 처음에는 폭 1360px 이상이면 "연습 매매"가 열려 있고, 그보다 좁으면 닫혀 있다. 마지막 상태는 브라우저에 기억된다.
- 폭 1100px 미만(모바일·태블릿)에서는 아이콘 줄 대신 위쪽에 **내 현황** 버튼이 있다. 누르면 같은 내용이 아래에서
  올라오는 시트로 열리고, 위의 탭(연습 매매 / 관심 / 최근 본 / 실시간)으로 바꾼다. 진행 중인 매매가 있으면 버튼에 빨간 점.
- 시트는 "닫기", 바깥 어두운 부분, Esc 로 닫는다. 목록의 항목을 눌러 다른 화면으로 가면 스스로 닫힌다.
  열려 있는 동안 초점이 시트 안에 머물고, 닫으면 "내 현황" 버튼으로 돌아간다.
- 등락률: 가격 조회(`/prices`) 응답에는 현재가만 있어서, 전일 종가를 일봉(`/candles?interval=1d`)에서 구한다.
  감시를 시작할 때와 날짜가 바뀔 때 종목당 한 번씩 뒤에서 받아 오고(0.2초 간격), 받기 전까지는 가격만 보인다.
  실패한 종목은 1분 뒤 다시 받는다. "오늘보다 앞선 날짜의 마지막 일봉 종가"를 전일 종가로 본다.
- 위 일봉 응답의 실제 모양(오늘 봉 포함 여부, 시각 표기)은 실제 API 로 확인하지 못했다. 두 경우 모두 같은 값이 나오게 날짜로
  걸러 내지만, 처음 실행할 때 토스증권 앱의 등락률과 한 번 비교해 볼 것.

### 실전까지 5단계

`증권사 연결 → 과거 데이터 받기(20일치) → 과거로 시험(통과) → 연습 매매(50번, 기준 통과) → 소액 실전`

앞 단계를 통과해야 다음이 "지금 여기"가 된다. 5단계(소액 실전)는 항상 잠겨 있다 —
실주문 기능이 아직 없기 때문이다. 통과 기준은 `PROFIT_PLAN.md` 와 같다
(표본 외 기대값 > 0, 신뢰구간 하한 > 0, 거래 수 충족).

### 데모

`--demo` 는 키 없이 가짜 서버(`devtools/fake_server.py`)와 가상 시계로 시나리오를 돌린다.

- 예시종목 A: 급락 후 반등 → 연습 매수 → 목표가에 팔림 (+2,009원)
- 예시종목 B: 같은 신호 → 연습 매수 → 손절 (−2,481원)
- 예시종목 C: 아무 일 없음

데모 기록은 `data/demo.sqlite` 에 따로 쌓이고 시작할 때마다 지운다. 실제 기록(`data/tradebot.sqlite`)과 섞이지 않는다.
**데모의 가격과 결과는 꾸며 낸 것**이라 전략이 실제로 통하는지와는 무관하다.

## 구조

```
ui/service.py      화면에 보여줄 내용 만들기 (금액 계산, 신호를 문장으로, 5단계, 설정 검증). HTTP 와 무관
ui/runtime.py      뒤에서 도는 것: 감시 스레드(Scanner), 과거 기록 받기·시험 작업, 데모 시나리오
ui/server.py       표준 라이브러리 http.server 로 만든 JSON API + 페이지 제공
ui/access.py       휴대폰 접속의 보호 장치 (접속 코드, 잠금, 주소 검사)
ui/qr.py           QR 코드 만들기
notify.py          휴대폰 알림 (텔레그램·ntfy). 화면과 `tradebot watch` 가 함께 쓴다
ui/static/index.html   한 장짜리 화면 (외부 스크립트 없음, 2초마다 상태 조회)
favorites.py       관심종목 파일 읽기·쓰기 (CLI 와 화면이 함께 씀)
```

추가 의존성은 없다. 화면에서 바꾼 설정은 `config/local.yaml` 에만 저장되고
(`strategy.yaml`·`risk.yaml` 의 주석을 보존하기 위해) 그 위에 덮어써진다. 손대지 않은 값은 저장하지 않는다.
`local.yaml` 을 지우면 기본값으로 돌아간다. CLI 명령(`watch`, `backtest` 등)도 같은 값을 쓴다.

### API

| 메서드 | 주소 | 설명 |
|---|---|---|
| GET | `/api/status` | 모드, 감시 상태, 진행 중인 매매, 5단계, 금액 예시, 오늘 있었던 일, 옆 패널용 관심종목 가격·오늘 합계 |
| GET | `/api/history` · `/api/signal?id=` | 연습 기록 · 신호 상세(그래프용 봉, 이유, 계획, 결과) |
| GET | `/api/favorites` · `/api/settings` · `/api/backtest` | 각 화면의 데이터 |
| POST | `/api/watch/start` · `/api/watch/stop` | 연습 매매 시작 · 멈춤 |
| POST | `/api/credentials` · `/api/auth/check` | 키 저장(.env, 권한 600) · 연결 확인 |
| POST | `/api/settings` | 거래 규칙 저장 (범위 검증) |
| POST | `/api/favorites/add` · `remove` · `toggle` | 관심종목 편집 |
| POST | `/api/backfill/run` · `/api/backtest/run` | 과거 기록 받기 · 시험 (백그라운드 작업) |

### 보호 장치

- 기본은 `127.0.0.1` 에만 연다. 같은 네트워크의 다른 기기에서는 접속할 수 없다.
- 모든 요청은 `Host` 가 이 컴퓨터를 가리켜야 한다 (DNS 리바인딩 차단).
- 값을 바꾸는 요청은 `X-Tradebot: 1` 헤더가 있어야 한다 (다른 웹사이트가 몰래 보내는 요청 차단).
- 키는 `.env` 에만 쓰고 어떤 응답에도 다시 내보내지 않는다. 화면에는 "저장됨" 여부만 보인다.
- 요청 본문은 64KB 로 제한, 설정값은 항목별 범위를 벗어나면 거부한다.

### 휴대폰에서 열기 (`--phone`)

`tradebot ui --phone` 으로 켜면 터미널에 내부 주소와 **접속 코드(6자리)** 가 나온다. 컴퓨터 화면의 설정 →
"휴대폰으로 열기"에서도 볼 수 있다. 휴대폰을 같은 와이파이에 연결하고 그 주소를 브라우저에 넣은 뒤 코드를 입력한다.

1. 컴퓨터에서 `tradebot ui --phone` (Mac 이 "들어오는 연결을 허용할까요?"라고 물으면 허용)
2. 휴대폰 카메라로 **QR 코드**를 찍는다 — 터미널과, 컴퓨터 화면의 설정 → "휴대폰으로 열기"에 나온다.
   주소와 접속 코드가 함께 들어 있어서 바로 홈 화면이 열린다
3. QR 을 못 쓰면: 휴대폰 브라우저 주소창에 `http://<컴퓨터 내부 주소>:8765` → 접속 코드 입력
4. 이후 30일 동안 그 휴대폰은 다시 묻지 않는다 (프로그램을 다시 켜도 유지. 데모에서는 다시 켜면 처음부터)

QR 코드는 `ui/qr.py` 에서 직접 만든다 (추가 설치 없음. 바이트 모드, 오류 복원 수준 M, 버전 1~10).
표준 QR 라이브러리의 출력과 184가지 경우(모든 버전·마스크)가 일치하는 것, 디코더로 읽히는 것을 개발 중에 확인했고,
그중 하나를 테스트에 고정값으로 넣어 두었다. QR 에는 접속 코드가 들어 있으므로 **화면의 QR 은 접속 코드와 똑같이 다룬다**
(사진을 찍어 남에게 보내지 말 것). 주소로 실려 온 코드는 코드 입력 화면이 받아 넣은 뒤 주소창에서 지운다.

#### 홈 화면에 앱처럼 추가

휴대폰에서 연 뒤 설정에 들어가면 방법이 나온다 (아이폰·안드로이드를 구분해 보여 준다).

- 아이폰: Safari → 공유 버튼 → "홈 화면에 추가". 아이콘으로 열면 주소창 없이 전체 화면으로 열린다.
  아이콘으로 여는 앱은 Safari 와 로그인을 따로 기억해서, 처음 한 번은 접속 코드를 다시 넣는다.
- 안드로이드: Chrome → ⋮ → "홈 화면에 추가". 휴대폰에 따라 주소창이 있는 화면으로 열릴 수 있다 (아래 한계 참고).
- 앱 이름 "웅덩이", 아이콘은 `ui/static/icon*.png` (파란 바탕에 내려갔다 올라오는 선). 앱 정보는 `manifest.webmanifest`.
- 앱처럼 쓰려면 프로그램을 다시 켤 때마다 코드를 묻지 않아야 해서, **한 번 들어온 휴대폰은 30일 동안 기억한다**
  (`data/ui_sessions.json`, 토큰의 해시만 저장, 권한 600). 컴퓨터 화면의 설정 → "휴대폰으로 열기"에서
  기억한 기기 수를 보고 **모두 끊을 수 있다**. 휴대폰을 잃어버렸거나 남이 들어온 것 같으면 끊으면 된다.
- 내부 주소(192.168.x.x)는 공유기가 바꿀 수 있다. 그러면 아이콘이 안 열리므로, 컴퓨터 화면에 함께 나오는
  이름 주소(`http://<컴퓨터 이름>.local:8765`)로 추가해 두면 더 오래 간다. 다만 이 이름 주소가 실제로 열리는지는
  기기에 따라 다르고 확인하지 못했다. 안 되면 숫자 주소를 쓴다.

한계: 통신이 HTTP 라서 휴대폰 브라우저가 "설치 가능한 앱"으로 취급하지 않는다. 그래서

- 꺼진 상태(오프라인)에서는 아무것도 안 열린다. 컴퓨터에서 프로그램이 켜져 있고 같은 와이파이여야 한다.
- 알림(푸시)은 없다.
- 안드로이드에서는 "앱 설치" 안내가 뜨지 않고 바로가기로 추가되며, 전체 화면으로 열리지 않을 수 있다.
- 아이폰·안드로이드 실제 기기에서 홈 화면에 추가해 보지는 못했다. 필요한 파일과 표시(meta)가 내려가는 것까지만 확인했다.

지키는 것 (`ui/access.py`):

- 코드를 넣기 전에는 코드 입력 화면만 내려가고, 모든 API 는 401 이다.
- 코드를 5번 틀리면 그 기기는 5분 동안 막힌다 (전체 합쳐 30번이면 모두 5분). 코드는 프로그램을 켤 때마다 새로 만든다.
- 아이콘과 앱 정보 파일(`/manifest.webmanifest`, `/icon*.png`)만 코드 없이 내려간다. 민감한 내용이 없다.
- 사설망(집·사무실 내부 주소)에서 온 요청만 받는다. 주소창 이름도 내부 숫자 주소·localhost·이 컴퓨터 이름만 허용한다.
- **키(Client ID·Secret)는 휴대폰에서 넣을 수 없다.** 그 밖의 기능(연습 시작·멈춤, 관심종목, 설정, 시험)은 된다.
- 접속 코드·내부 주소·QR 코드는 컴퓨터(127.0.0.1)로 연 화면에만 보인다.

한계 — 알고 써야 하는 것:

- **통신이 암호화되지 않는다 (HTTP).** 같은 와이파이에서 통신을 엿볼 수 있는 사람은 화면 내용과 로그인 쿠키를 볼 수 있다.
  집처럼 믿을 수 있는 와이파이에서만 켜고, 카페·공용 와이파이에서는 켜지 말 것. 키 입력을 휴대폰에서 막은 이유도 이것이다.
- 같은 와이파이 안에서만 된다. 밖(이동통신망)에서 접속하는 기능은 없고, 공유기 포트를 열어 밖에서 들어오게 만들지 말 것.
- 컴퓨터가 잠들면 끊긴다. 내부 주소는 공유기가 바꿀 수 있어서, 안 열리면 터미널이나 설정 화면의 주소를 다시 확인한다.
- 이 기능은 가짜 네트워크 주소로만 시험했다. 실제 휴대폰·공유기·Mac 방화벽 조합에서는 확인하지 못했다.

### 휴대폰 알림

연습으로 샀을 때와 팔았을 때(결과) 휴대폰으로 알림을 보낸다. 설정 → "휴대폰 알림"에서 켠다.
화면(집 와이파이의 HTTP)만으로는 휴대폰에 알림을 띄울 수 없어서 **바깥 알림 서비스를 거친다.** 둘 중 하나를 고른다.

| 방법 | 준비 | 특징 |
|---|---|---|
| ntfy 앱 | 앱 설치 → 화면에 나온 "주제 이름" 구독 | 가장 간단. 가입 없음. 주제 이름을 아는 사람은 누구나 그 알림을 읽고 쓸 수 있어서, 프로그램이 추측하기 어려운 이름을 만든다 |
| 텔레그램 | @BotFather 로 봇 만들기 → 토큰 붙여넣기 → 봇에게 한마디 → 시험 알림 | 이미 텔레그램을 쓰면 편하다. 대화방은 프로그램이 찾아 준다 |

- 알림 예: `신호 · 삼성전자 연습 매수` / `99,300원 × 3주를 연습으로 샀어요. 목표 100,200원 / 손절 98,800원 / 10:36까지`
  그리고 `삼성전자 · 손절로 팔았어요 −2,481원`. 모든 알림에 "연습 매매 · 실제 주문 없음"이 붙는다. 데모에서는 제목 앞에 `[데모]`.
- **알림을 누르면 그 신호 화면이 열린다.** 알림에 `http://<컴퓨터 내부 주소>:8765/#/signal/<신호>` 주소를 붙인다
  (ntfy 는 알림 자체를 누르면, 텔레그램은 메시지 아래 "신호 화면 열기" 버튼을 누르면 열린다).
  - `tradebot ui --phone` 으로 켰을 때만 붙는다. 이 컴퓨터 전용으로 켰거나 `tradebot watch` 로 돌릴 때는 휴대폰이 열 주소가 없다.
  - 휴대폰이 같은 와이파이에 있어야 열린다. 밖에서는 알림은 오지만 눌러도 열리지 않는다.
  - 그 휴대폰이 아직 접속 코드를 넣은 적이 없으면 코드 입력 화면이 먼저 나오고, 넣으면 그 신호 화면으로 이어진다.
    접속 코드는 알림에 넣지 않는다 (알림이 바깥 서비스를 거치기 때문).
  - 아이폰에서 홈 화면 아이콘으로 쓰고 있어도, 알림의 주소는 Safari 로 열린다.
  - 텔레그램이 집 안 주소가 든 버튼을 거절하면, 주소를 글로 붙여 다시 보낸다 (알림은 빠지지 않는다).
    실제 텔레그램이 어느 쪽으로 동작하는지는 확인하지 못했다.
  - 이 주소(컴퓨터의 내부 주소와 포트)도 알림과 함께 그 서비스로 전달된다.
- 집 밖(이동통신)에서도 받는다. 다만 컴퓨터에서 프로그램이 켜져 있고 연습(감시) 중이어야 신호가 생긴다.
- `tradebot watch` 로 터미널에서 돌릴 때도 같은 설정으로 알림이 나간다.
- 구현은 `notify.py`. 알림은 뒤에서 줄 세워 보내고(초당 1건), 실패해도 감시는 멈추지 않는다.
  마지막 알림이 실패했으면 설정 화면에 이유가 보인다.

알고 써야 하는 것:

- **종목 이름·가격·연습 손익이 그 서비스(텔레그램 또는 ntfy.sh)로 전달된다.** 계좌 정보와 토스증권 키는 보내지 않는다.
  설정하기 전에는 아무것도 밖으로 나가지 않는다.
- 텔레그램 토큰과 ntfy 주제 이름은 `.env` 에만 저장한다(권한 600). 토큰은 화면에 다시 보여주지 않고,
  주제 이름은 컴퓨터로 연 화면에만 보인다. 알림 설정은 컴퓨터에서만 바꿀 수 있다 (휴대폰에서는 시험 알림만).
- 알림이 늦거나 빠질 수 있다. 알림만 믿고 판단하지 말고 화면의 기록을 기준으로 삼을 것.
- **실제 텔레그램·ntfy 서버로는 보내 보지 못했다** (개발 환경에서 두 서비스에 접속 불가). 두 서비스의 공개된
  요청 형식을 따르는 가짜 서버로만 시험했다. 처음 켤 때 "시험 알림 보내기"로 꼭 확인할 것.

## 디자인

토스증권 PC 화면의 디자인 언어(TDS)를 가져왔다. `ui/static/index.html` 맨 위의 CSS 변수가 전부다.

| 항목 | 밝은 화면 | 어두운 화면 |
|---|---|---|
| 바탕 / 카드 | `#F2F4F6` / `#FFFFFF` | `#17171C` / `#202027` |
| 카드 안 옅은 칸 · 입력창 | `#F9FAFB` · `#F2F4F6` | `#26262E` · `#2C2C35` |
| 글자 (제목 / 본문 / 보조) | `#191F28` / `#333D4B` / `#6B7684` | `#FFFFFF` / `#E4E4E5` / `#9E9EA4` |
| 구분선 | `#E5E8EB` | `#2C2C35` |
| 강조·주 버튼 (토스 블루) | `#3182F6` | `#3485FA` |
| 오름 / 내림 | `#F04452` / `#3182F6` | `#F04452` / `#3485FA` |

- 카드는 테두리 없이 모서리 20px, 버튼 12px(작은 버튼 10px), 배지 6px, 입력창 12px.
- 주 버튼은 파랑 바탕에 흰 글자, 보조 버튼은 회색 바탕(테두리 없음). 입력창은 회색 바탕이고 누르면 파란 테두리.
- 위쪽 메뉴 줄 높이 60px, 내용 폭 최대 1140px.
- 글꼴: `Toss Product Sans`(컴퓨터에 설치돼 있을 때만) → Pretendard(CDN) → 시스템 글꼴 순서.

**가져오지 않은 것과 한계**

- 토스 로고·이름·전용 글꼴 파일은 쓰지 않는다. 이 프로그램은 토스증권이 만든 것이 아니고, 화면 이름도 "웅덩이 트레이더"다.
- 개발 환경에서 tossinvest.com 이 막혀 있어 실제 화면과 나란히 놓고 비교하지 못했다.
  색·모서리 값은 공개적으로 알려진 TDS 값을 기억에 의존해 옮긴 것이라, 실제 토스증권 PC 와 어긋나는 곳이 있을 수 있다.
  어긋난 곳을 알려 주면 CSS 변수만 고치면 된다.
- 토스 블루가 "주 버튼"과 "내림" 양쪽에 쓰인다 (토스도 같다). 금액에는 항상 부호(+/−)와 ▲▼ 를 함께 적어 구분한다.
