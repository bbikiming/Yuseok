# 화면 (로컬 웹 UI)

주식을 잘 모르는 사람도 쓸 수 있게 만든 화면이다. 터미널 명령을 외우지 않아도
키 연결 → 과거 기록 받기 → 과거로 시험 → 연습 매매까지 브라우저에서 할 수 있다.

```bash
tradebot ui --demo     # 키 없이 가상 데이터로 둘러보기 (약 3분짜리 시나리오)
tradebot ui            # 실제 사용. http://127.0.0.1:8765 가 열린다
tradebot ui --port 9000 --no-open
```

저장소 폴더(설정 `config/` 가 있는 곳)에서 실행한다. 끝낼 때는 터미널에서 Ctrl-C.

## 설계 원칙

1. **퍼센트보다 원.** "+0.9%" 대신 "약 +2,004원". 수수료·세금을 뺀 금액을 보여 준다.
2. **용어보다 문장.** "손절가 도달" 대신 "가격이 98,800원 아래로 내려가서 약속대로 팔았어요".
3. **연습이라는 사실을 항상 보이게.** 모든 화면 위에 "연습 모드 · 실제 주문 없음" 표시.
   실제 주문을 켜는 버튼·설정은 없다 (그런 코드 자체가 없다).
4. **근거 없는 숫자를 만들지 않는다.** 승률·누적 수익은 실제 기록에서만 계산한다.
   기록이 모자라면 "아직 판단할 수 없어요"라고 말한다.
5. **불리한 사실도 그대로.** 지금 기본 설정은 주식 기준 10번 중 6번을 이겨야 본전이라는 것,
   손절은 한 칸 낮은 가격에 팔린 것으로 계산한다는 것을 화면에 적는다.
6. **색 약속은 한국 증시 관례.** 오르면 빨강, 내리면 파랑. 색만으로 구분하지 않고 ▲▼·글자를 함께 쓴다.

## 화면

| 화면 | 주소 | 내용 |
|---|---|---|
| 홈 | `#/` | 지금 상태 한 문장 + 다음에 할 일 버튼, 실전까지 5단계, 진행 중인 연습 매매(목표가·손절가 사이 어디쯤인지), 한 번 거래하면 오가는 금액, 오늘 있었던 일 |
| 신호 | `#/signals` | 오늘 연습으로 산 기록 목록 |
| 신호 상세 | `#/signal/<id>` | 왜 샀는지(그래프 + 세 문장), 언제 파는지(세 가지 경우와 금액), 끝났으면 결과와 계산 내역 |
| 관심종목 | `#/favorites` | 지켜볼 종목 켜기/끄기·추가·삭제, 종목 고르는 요령 |
| 과거로 시험 | `#/backtest` | 과거 기록 받기, 규칙이 과거에 통했는지 판정(통과 / 통과 못 함 / 판정 보류) |
| 연습 기록 | `#/history` | 지금까지의 연습 결과 합계, 50번 중 몇 번 쌓였는지, 전체 목록 |
| 설정 | `#/settings` | 토스증권 키 연결, 거래 규칙(금액·목표·손절·시간·횟수·수수료·세금), 바꾼 값에 따른 금액 미리보기 |

PC는 왼쪽 메뉴, 760px 미만(모바일)은 아래 탭 메뉴로 바뀐다. 같은 페이지 한 장이 두 형태를 겸한다.

### 실전까지 5단계

`증권사 연결 → 과거 데이터 받기(20일치) → 과거로 시험(통과) → 연습 매매(50번, 기준 통과) → 소액 실전`

앞 단계를 통과해야 다음이 "지금 여기"가 된다. 5단계(소액 실전)는 항상 잠겨 있다 —
실주문 기능이 아직 없기 때문이다. 통과 기준은 `PROFIT_PLAN.md` 와 같다
(표본 외 기대값 > 0, 신뢰구간 하한 > 0, 거래 수 충족).

### 데모

`--demo` 는 키 없이 가짜 서버(`devtools/fake_server.py`)와 가상 시계로 시나리오를 돌린다.

- 예시종목 A: 급락 후 반등 → 연습 매수 → 목표가에 팔림 (+2,009원)
- 예시종목 B: 같은 신호 → 연습 매수 → 손절 (−2,481원)
- 예시종목 C: 아무 일 없음

데모 기록은 `data/demo.sqlite` 에 따로 쌓이고 시작할 때마다 지운다. 실제 기록(`data/tradebot.sqlite`)과 섞이지 않는다.
**데모의 가격과 결과는 꾸며 낸 것**이라 전략이 실제로 통하는지와는 무관하다.

## 구조

```
ui/service.py      화면에 보여줄 내용 만들기 (금액 계산, 신호를 문장으로, 5단계, 설정 검증). HTTP 와 무관
ui/runtime.py      뒤에서 도는 것: 감시 스레드(Scanner), 과거 기록 받기·시험 작업, 데모 시나리오
ui/server.py       표준 라이브러리 http.server 로 만든 JSON API + 페이지 제공
ui/static/index.html   한 장짜리 화면 (외부 스크립트 없음, 2초마다 상태 조회)
favorites.py       관심종목 파일 읽기·쓰기 (CLI 와 화면이 함께 씀)
```

추가 의존성은 없다. 화면에서 바꾼 설정은 `config/local.yaml` 에만 저장되고
(`strategy.yaml`·`risk.yaml` 의 주석을 보존하기 위해) 그 위에 덮어써진다. 손대지 않은 값은 저장하지 않는다.
`local.yaml` 을 지우면 기본값으로 돌아간다. CLI 명령(`watch`, `backtest` 등)도 같은 값을 쓴다.

### API

| 메서드 | 주소 | 설명 |
|---|---|---|
| GET | `/api/status` | 모드, 감시 상태, 진행 중인 매매, 5단계, 금액 예시, 오늘 있었던 일 |
| GET | `/api/history` · `/api/signal?id=` | 연습 기록 · 신호 상세(그래프용 봉, 이유, 계획, 결과) |
| GET | `/api/favorites` · `/api/settings` · `/api/backtest` | 각 화면의 데이터 |
| POST | `/api/watch/start` · `/api/watch/stop` | 연습 매매 시작 · 멈춤 |
| POST | `/api/credentials` · `/api/auth/check` | 키 저장(.env, 권한 600) · 연결 확인 |
| POST | `/api/settings` | 거래 규칙 저장 (범위 검증) |
| POST | `/api/favorites/add` · `remove` · `toggle` | 관심종목 편집 |
| POST | `/api/backfill/run` · `/api/backtest/run` | 과거 기록 받기 · 시험 (백그라운드 작업) |

### 보호 장치

- `127.0.0.1` 에만 연다. 같은 네트워크의 다른 기기에서는 접속할 수 없다.
  (휴대폰에서 보려면 같은 컴퓨터의 브라우저를 좁게 하거나, 따로 터널을 직접 구성해야 한다.)
- 모든 요청은 `Host` 가 `127.0.0.1`/`localhost` 여야 한다 (DNS 리바인딩 차단).
- 값을 바꾸는 요청은 `X-Tradebot: 1` 헤더가 있어야 한다 (다른 웹사이트가 몰래 보내는 요청 차단).
- 키는 `.env` 에만 쓰고 어떤 응답에도 다시 내보내지 않는다. 화면에는 "저장됨" 여부만 보인다.
- 요청 본문은 64KB 로 제한, 설정값은 항목별 범위를 벗어나면 거부한다.

## 검증 상태

- `tests/test_ui.py` (20개): 금액·문장 계산, 설정 저장, 관심종목, 키 저장 권한, 서버 보호 장치,
  기록·신호 상세, 판정 보류, 데모에서 연습 매수가 일어나는지.
- 데모 시나리오 전체(A 목표가, B 손절)와 화면 조작(종목 추가·끄기, 설정 저장, 키 저장)은
  브라우저 자동화로 PC(1440px)·모바일(390px)에서 확인했다. 콘솔 오류 없음.
- **확인하지 못한 것:** 실제 토스증권 API 에 연결된 상태의 화면. 개발 환경에서 tossinvest.com 이
  막혀 있어 "연결됨" 상태, 실제 과거 기록 받기, 실제 장중 감시는 가짜 서버로만 돌려 봤다.
  메인 PC 에서 키를 넣고 처음 실행할 때 확인이 필요하다.
