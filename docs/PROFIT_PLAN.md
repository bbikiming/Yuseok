# 최신화 분석 + 단타 수익화 플랜 (2026-11-14)

6월 스켈레톤 이후 프로젝트 현황을 다시 점검하고, 지금 손에 있는 데이터로 수익 가능성을
가장 빨리 검증하는 순서를 정리한다. 결론부터:

1. **현재 설정(대형주 + TP 0.9% / SL 0.5% + 승률 게이트 55%)은 비용을 빼면 손실 구조다.**
   손익분기 승률이 62~66%인데 게이트는 55%에서 통과시킨다.
2. 쌓인 가상매매 데이터는 없다(수집 루프가 스텁). 대신 **토스 API의 과거 1분봉**이 바로 쓸 수 있는
   기존 데이터다. paper로 몇 달 기다리지 말고 백테스트부터 한다.
3. 비용 구조상 **ETF(거래세 면제, 호가단위 5원)** 가 같은 전략의 손익분기를 40%대로 낮춘다.
   종목군 선택이 파라미터 튜닝보다 영향이 크다.

수익을 보장하는 계획이 아니다. 엣지가 있는지 싸게 확인하고, 없으면 실거래 전에 접는 계획이다.

## 2. 가장 큰 문제: 비용을 넣으면 현재 설정은 음수 기대값

왕복 비용 = 수수료 0.015%×2 + 매도 거래세 + 스프레드(호가단위/주가).

| 시나리오 | 왕복비용 | TP 0.9 / SL 0.5 손익분기 승률 | 승률 55%일 때 기대값 |
|---|---:|---:|---:|
| 대형주, 시장가 왕복 (5~20만원대, 틱 0.14%) | 0.37% | 62.1% | -0.10%/회 |
| 대형주, 시장가 왕복 (20~50만원대, 틱 0.19%) | 0.42% | 65.7% | -0.15%/회 |
| 대형주, 지정가 진입 + 시장가 청산 | 0.30% | 57.1% | -0.03%/회 |
| ETF, 시장가 왕복 (거래세 0, 스프레드 0.03% 가정) | 0.06% | 40.0% | +0.21%/회 |

- TP1 +0.5%에서 전량 익절하면 대형주는 손익분기 승률이 87~92%가 된다. 사실상 불가능.
- 거래세는 2026년 기준 0.20%로 계산했다. 세율과 수수료는 추정하지 말고
  `/api/v1/commissions`와 실제 체결의 `tax` 필드로 확정할 것.
- ETF 스프레드 0.03%는 유동성 큰 종목 기준 가정치다. 호가 스냅샷으로 종목별 실측 필요.
- TIMEOUT(시간청산)은 위 표에 없다. 실제로는 비용만 내고 끝나는 거래라 기대값을 더 깎는다.

**영향받는 설정/코드**
- `ml/evaluation.py`의 `GATE.min_win_rate = 0.55` → 승률 기준을 없애고
  "비용 반영 기대값 > 0, 신뢰구간 하한 > 0"으로 교체.
- `config/strategy.yaml`, `config/risk.yaml`에 exit 값이 중복 정의됨 → 한 곳으로 통일.
- PRD §11.7, §18.2의 "승률 55% 이상이면 긍정 검토"도 같은 이유로 수정 대상.

## 3. 쓸 수 있는 "기존 데이터"

| 데이터 | 출처 | 용도 | 확인 필요 |
|---|---|---|---|
| 과거 1분봉 | `/candles?interval=1m` + `before` 페이징 | 백테스트 본체 | **얼마나 과거까지 주는지** (스펙에 없음. 첫 실험) |
| 과거 일봉 | `/candles?interval=1d` | 변동성·거래대금 기준 종목 선별, 장세 필터 | — |
| 종목 메타 | `/stocks` (`securityType`, `leverageFactor`) | ETF/주식 구분, 비용 모델 분기 | — |
| 본인 과거 체결 | `/orders?status=CLOSED` | 수동 단타 실적과 전략 비교 | 스펙 내 설명이 모순(`closed-not-supported` 언급). 실호출로 확인 |
| 호가·체결 틱 | `/orderbook`, `/trades` | 스프레드 실측, 체결 모델 보정 | **과거분 없음.** 지금부터 수집해야 쌓임 |

1분봉 백필이 되면 관심종목 10~20개 × 수십 거래일에서 신호 수백 개를 하루 만에 만들 수 있다.
PRD의 "20거래일 + 신호 100개" 대기 시간을 건너뛴다.

## 4. 실행 플랜

각 단계는 통과 기준을 못 넘으면 다음으로 가지 않는다.

### 0단계 — 동기화 (반나절)
- 정본 저장소를 `stock-auto-trader`로 확정. Yuseok PR #1은 닫는다.
- 맥에서 `python split_openapi.py`로 최신 스펙을 받아 v1.1.1과 diff
  (WebSocket 지원 여부, 캔들 주기 추가 여부가 핵심).
- `tradebot auth test` 통과, `/commissions` 실제 수수료율 기록.

### 1단계 — 데이터 백필 (1~2일)
- `tradebot backfill --interval 1m`: `before` 커서로 더 못 받을 때까지 과거로 페이징, `candles`에 upsert.
- 후보 종목군: 현재 관심종목 + 유동성 큰 ETF(지수, 반도체 섹터, 레버리지).
- 동시에 `watch` 수집 루프를 구현해 호가 스냅샷을 쌓기 시작(스프레드 실측용).
- **통과 기준**: 종목당 1분봉 20거래일 이상 확보. 미달이면 수집을 돌려 쌓으면서 일봉 기반 분석만 선행.

### 2단계 — 백테스트 엔진 (3~5일)
- 탐지기(C1~C10)를 순수함수로 구현, 과거 1분봉을 시간순으로 리플레이.
- 체결 모델(보수적으로):
  - 진입: 신호 봉의 **다음 봉 시가** + 1틱 불리하게
  - 청산: 같은 봉에서 TP·SL 동시 터치 시 **SL 우선**
  - 비용: 실제 수수료 + 종목 유형별 거래세 + 틱 기반 스프레드
- 미완성 봉 제외(현재 `candles.resample`은 진행 중인 마지막 봉을 포함함. 수정 필요).
- 결과는 기존 `signals` / `paper_trades` 스키마에 `source=backtest`로 적재해 학습 루프와 공유.

### 3단계 — 엣지 탐색 (2~3일)
- 가설은 미리 적어두고 소수만 검증한다(과최적화 방지):
  1. 종목군: 대형주 vs ETF
  2. TP/SL 비율: 0.9/0.5, 1.2/0.6, 1.5/0.7
  3. 하락폭 구간: -1.2~-2%, -2~-3.5%
  4. 장세 필터(지수 급락 중 제외) 유무
  5. 시간대: 장초반 30분 제외 유무
- 데이터 앞 70%로 고르고, 뒤 30%는 마지막에 한 번만 본다.
- **통과 기준**: 뒤 30%에서 비용 후 기대값 > 0, 거래 50회 이상, 부트스트랩 신뢰구간 하한 > 0.
- **중단 기준**: 어떤 조합도 통과 못 하면 웅덩이 반등 전략은 이 비용 구조에서 엣지가 없다는 결론.
  실거래로 가지 않고 전략 가설 자체를 바꾼다(PRD §22.3의 돌파·VWAP 등).

### 4단계 — paper 전진 검증 (2~4주)
- 3단계 통과 조합만 `watch --mode paper`로 실시간 운용.
- 백테스트 대비 괴리 측정: 신호 빈도, 승률, 평균 손익. 괴리가 크면 체결 모델이 낙관적이었던 것.
- 이 구간 데이터부터 호가/틱 feature가 붙으므로 ML(Phase 4)은 여기서 시작.
- **통과 기준**: paper 기대값이 백테스트 신뢰구간 안, 비용 후 양수.

### 5단계 — 소액 실거래 (manual)
- 1회 30만원, 하루 3회, 일손실 한도 유지. 사용자가 `approve`한 것만 주문.
- 실제 체결가로 슬리피지를 재서 체결 모델 재보정.
- 30만원 기준 +0.2%/회면 회당 600원이다. 이 단계의 목적은 수익이 아니라 실체결 검증이고,
  금액 확대는 실거래 50회 이상에서 기대값이 유지될 때만.

## 5. 코드 최신화 항목

우선순위 순.

1. **토큰 파일 캐시** — 지금은 메모리 캐시라 CLI를 실행할 때마다 토큰을 재발급하고,
   client당 토큰 1개 제약 때문에 돌고 있던 `watch`의 토큰이 무효화된다. `data/.token` 등에 저장.
2. **게이트 교체** — §2 참고.
3. **미완성 봉 처리** — `resample`과 탐지기에서 진행 중인 봉 제외.
4. **`change_rate` 계산** — `/prices`는 현재가만 준다. 전일 종가(일봉)로 직접 계산.
5. **체결강도 근사** — `/trades`에 매수/매도 구분이 없다. 틱 룰(직전가 대비 상승=매수)로 추정하거나 C8을 뺀다.
6. **exit 설정 단일화** — `strategy.yaml` / `risk.yaml` 중복 제거.
7. **5xx 재시도 없음** — 조회 API에 한해 백오프 재시도 추가(주문 API는 제외).
8. `IMPLEMENTATION_PLAN.md` 순서 변경 — Phase 1 뒤에 "백필 + 백테스트"를 넣고 paper를 그 뒤로.
